# v0.2 验收计划

## 1. 使用规则

本文把验收严格分为：

1. **当前 Linux 可验证基线**：验证仓库已经实现的 Go 数据面、Swift 协议/规则核心及 fail-closed 模板边界。
2. **必须在 Xcode 与物理 iPad 验证的 v0.2 release gate**：验证 NetworkExtension、user-space TCP/IP stack、Network.framework、DNS/FakeIP、系统生命周期、内存和真实网络行为。

Linux 基线全部通过也不表示 v0.2 iPad 数据面完成。模拟器或 macOS unit test 可用于开发，但不能替代标为“物理 iPad”的门禁。

每条记录必须包含：日期、commit SHA、设备型号、iPadOS/Xcode 版本、relay commit、配置摘要、操作步骤、原始测试输出或脱敏日志、结果和缺陷链接。结果只能写 `PASS`、`FAIL`、`BLOCKED` 或 `NOT RUN`。没有证据不得写 `PASS`。

当前仓库状态：Foundation-based Swift core 已实现 protocol、规则索引、DNS/FakeIP/RuleStore/FlowRouter 和 transport boundary；Apple-only template 也已有 TLS、DIRECT、Keychain、App Group 与 generation-aware provider 生命周期代码。它们仍未组成可运行 Packet Tunnel：仓库没有 user-space TCP/IP stack adapter、Xcode containing app/extension 工程、entitlement、provisioning 或真机证据；上游 DNS I/O、FakeIP flow lease/quarantine 和规则 manifest crash recovery 仍待后续接入。因此第 3 节在现状下应为 `BLOCKED` 或 `NOT RUN`，不得标记为完成。

## 2. 当前 Linux 可验证基线

所有命令从仓库根目录执行，除非步骤另有说明。

### LNX-01 Go 完整门禁

**操作**

```sh
go test ./...
go vet ./...
go test -race ./...
go build ./...
```

**通过条件**

- 四条命令 exit code 都为 0；
- race detector 无报告；
- 无 crash、deadlock 或测试超时。

**证明范围**

Go protocol、config、SOCKS5 client、TLS relay、TCP/UDP relay 和现有测试通过。该项不编译或验证 Packet Tunnel。

### LNX-02 Go 本地 TCP/UDP 端到端重复测试

**操作**

```sh
go test ./internal/client -run TestLocalEndToEndTCPAndUDP -count=20
```

**通过条件**

- 20 次全部通过；
- TLS 建连、token 认证、TCP half-close 和 UDP datagram 边界无间歇失败；
- 测试中的本地 echo 仅用于测试。测试启用 private destination 不表示生产配置允许私网目标。

### LNX-03 Go 协议、策略与严格配置

**操作**

```sh
go test ./internal/protocol -count=20
go test ./internal/config -count=20
go test ./internal/server -count=20
go test ./internal/client -run 'Test(SocksNegotiation|SocksRequestAddresses|UDPCodecAndFragment|RejectInvalidSocks|SocksPortEncoding)$' -count=20
```

必须从 verbose 输出或 `go test -list . ./internal/client` 确认上述五个测试都实际运行；任一测试未运行即不通过。

**通过条件**

- 0、超长、截断、未知版本/命令/status/address type 和非法地址 frame 被拒绝；
- token 长度、response message 和 UDP payload 边界生效；
- loopback、private、link-local、multicast 和 unspecified destination 默认被 server 拒绝；
- UDP 未联系 endpoint 不能向 association 注入响应；
- 未知 JSON 字段、第二个 JSON 值、错误 token/hash 和非正 duration 被拒绝；
- SOCKS5 UDP `FRAG != 0` 被丢弃。

### LNX-04 Swift core 门禁

**操作**

```sh
cd ios
swift test
```

**通过条件**

- build 和全部 test exit code 为 0；
- Go v1 对应的 frame、Address、Request、Response、Datagram golden/boundary test 通过；
- token 和 auth request 的 description、debug description、Mirror 不暴露 token；
- rule 按 JSON 数组原顺序 first-match，20,000 条 iOS runtime 上限生效；
- `domain`、`domain_suffix`、`domain_keyword`、IPv4/IPv6 CIDR、单 port 和 `final` 行为通过；
- strict JSON、version、timestamp、规则数、枚举和值校验通过；
- FakeIP 当前的稳定映射、双栈、固定权威 TTL、不驱逐有效项、过期回收和每族容量测试通过；
- DNS 当前的 A/AAAA synthesis、DIRECT/REJECT、携带 action 的其他 qtype forward、EDNS(0)、非法 compression/malformed input 与 TCP framing 测试通过；
- RuleStore 当前的 32 MiB 输入上限、decode/compile-before-publish、Foundation `.atomic` 持久化、startup load 和失败保留旧 generation 测试通过；
- FlowRouter 三分支、PROXY 失败不回退及有界 transport test double 通过。

**证明范围**

`swift test` 可证明上述纯 Foundation 单元行为，但不能证明 Apple 接入已经完成。当前 DNS 已保留 forward action，FakeIP 访问不会续期且不会驱逐有效项，RuleStore 已有输入 byte cap；flow lease/quarantine、manifest/current/previous、directory fsync、上游 DNS I/O 和 user-space TCP/IP stack 仍待后续接入。该命令不编译 `PacketTunnelTemplate`，不能证明 NetworkExtension、Network.framework、Keychain/App Group、签名或真机网络行为。

### LNX-05 Packet Tunnel fail-closed 边界审查

**操作**

人工审查：

- `ios/Package.swift`
- `ios/README.md`
- `ios/PacketTunnelTemplate/PacketTunnelProvider.swift`

**通过条件**

- template 不属于 Swift Package target；
- `makeDependencies()` 默认抛出 `missingDependencies`，所以 template 不能启动可运行 tunnel；
- network settings 成功前不调用 packet-stack `start`；
- 不存在绕过规则的直接放行路径；
- 当前模板已用 MainActor 串行化 generation、用一次性 completion 防重复回调，并让重复 stop 等待同一清理任务；仍未实现 5 秒强制清理预算，也尚未经过 Xcode 并发诊断和真机竞态测试。

**解释**

该项通过只证明当前 template 默认安全失败，不证明 Apple API 可编译或 v0.2 tunnel 已实现。

### LNX-06 当前 UDP-over-TLS 限制

**操作**

结合 Go/Swift protocol test 与源码审查确认：

- 每个 UDP association 独占一条 TLS connection；
- frame body 最大 65,600 bytes；
- UDP payload 最大 65,507 bytes，且完整 body 仍受 target address 长度限制；
- 253-byte domain 时最大 payload 为 65,342 bytes；
- 空 payload 合法；
- `FRAG != 0` 不支持；
- association 有 idle timeout；
- TCP head-of-line blocking 是已知限制。

**通过条件**

文档、Go codec 和 Swift codec 对边界定义一致。不得把此项描述为 QUIC 或无阻塞 UDP transport。

### LNX-07 当前安全与日志边界

**操作**

审查运行日志调用和协议错误文本，并运行相关 Go/Swift tests。

**通过条件**

- 现有运行日志不记录 token 或 payload；
- Swift token/request 的字符串与 reflection 输出脱敏；
- relay response 使用泛化错误文本，不返回内部地址详情；
- client config 被视为 secret；
- server 默认执行 private destination 防护。

**已知缺口**

Go `AuthRequest` 自身没有通用日志脱敏包装，因此后续实现仍禁止直接记录整个 request。当前 Go active connection/goroutine 没有全局容量上限；UDP peer set 已按 association 限制为 256 项并在 60 秒无活动后过期。

### LNX-08 v0.2 core 与 relay 增量门禁

以下行为可在 Linux 做确定性测试，必须先通过，不能留到真机才发现。当前源码仍有已知差距，因此没有新增测试证据时本项为 `FAIL` 或 `NOT RUN`。

**必须新增并运行的测试组**

```sh
cd ios
swift test --filter DNSProxyCoreTests
swift test --filter FakeIPStoreTests
swift test --filter RuleStoreTests
swift test --filter RuleEngineTests
cd ..
go test -race ./internal/server -run 'Test.*UDPPeer' -count=20
```

测试名称可以随实现调整，但测试清单和输出必须证明：

- DNS 对所有允许转发的 qtype 保留 `DIRECT`/`PROXY` action；PROXY A/AAAA 按 Fake-IP 模式合成地址并由 relay 在连接时解析真实域名；
- DNS compression pointer 拒绝指向 header、当前/未来位置、循环、越界和展开后超长；支持并验证一个 EDNS(0) OPT；
- FakeIP 正向访问和反查不延长权威 TTL；未过期映射不因容量压力被驱逐；
- iOS runtime 规则上限为 20,000，输入上限为 32 MiB；持久化失败保留旧 generation；
- Go relay 每 UDP association 最多保留 256 个 contacted peer，每项 60 秒无活动过期；达到上限、过期和并发访问在 race detector 下通过。

**通过条件**

所有测试 exit code 为 0，且不得通过删除断言、放宽安全默认值或把 action 默认为 DIRECT 来满足测试。

## 3. 必须在 Xcode 与物理 iPad 验证的 v0.2 release gate

### 3.1 前置条件

开始 release gate 前必须具备：

- containing app 和 Packet Tunnel Extension targets；
- 正确的 provider class、NetworkExtension entitlement、App ID 和 provisioning；
- App Group 与 Keychain access group；
- 已评审的 user-space TCP/IP stack adapter；
- 已完成设计增量的 DNSProxyCore、FakeIPStore、RuleStore 和 FlowRouter；
- 新增 DIRECT Network.framework backend；
- Apple template 中的 TLS transport、Keychain store、App Group store 和 provider 已通过 Xcode compile/unit test；
- 与待测 commit 对应的 Go relay，包含有界 UDP peer set；
- 可采集 extension memory、CPU、task、timer、flow、queue 与错误计数的脱敏诊断。

缺少任一项时，相关条目标记 `BLOCKED`，不能用 template、mock 或 Linux test 代替。

### IOS-01 构建、签名与安装

**环境**：Xcode Release configuration + 物理 iPad。

**操作**

1. clean build containing app 和 extension；
2. 安装到目标 iPad；
3. 首次启动，写入测试 relay 配置和 Keychain token；
4. 创建并启用 VPN configuration；
5. 重启设备后再次启动 app 与 tunnel。

**通过条件**

- app 与 extension 均签名成功并可加载；
- entitlement、App Group 和 Keychain access 正常；
- token 不进入普通配置、console 或诊断导出；
- 重启后配置仍可读取；
- 没有 Xcode 工程、签名和真机安装证据时，本项不得通过。

本项验证开发/测试安装，不代表已产出商店包、IPA 或发布流程。

### IOS-02 start/stop 状态机

**环境**：Xcode instrumentation + 物理 iPad。

**操作**

1. 正常 start/stop 连续 100 次；
2. 分别在配置读取、Keychain、规则装载、IP stack 初始化、network settings、TLS handshake 阶段注入失败；
3. 在 `starting` 的每个阶段调用 stop，并断言 start completion 先收到 cancellation error，随后所有 stop completion 才完成；
4. 在 `stopping` 连续提交多个 stop，断言只清理一次且所有 completion 等待同一终态；
5. 在 `running` 时用可控 scheduler 交错 stop、fatal network error、connector completion 和旧 generation 迟到回调；
6. 在 completion 内同步再次 start，验证终态与资源引用已先发布/清空；
7. 让一个 adapter 故意不响应取消，验证 5 秒 cleanup timeout；
8. stop 完成后立即重新 start，并对重复 start/stop 做压力测试。

**通过条件**

- 转换只符合 `stopped -> starting -> running -> stopping -> stopped` 或失败路径；
- start/stop completion 各调用一次且仅一次；多个 stopping 期间的 stop completion 全部在同一次清理后完成；
- stop-during-start 先完成带 cancellation error 的 start completion，再完成 stop completion；
- network settings 和全部依赖 ready 前不读取 packet；
- 启动失败不会留下 packet read、task、timer、connection 或内存 token 引用；
- stop 先停止新 packet/flow，再取消 DNS、TLS、TCP、UDP、timer 和 queue；
- 正常停止 5 秒内完成；不合作资源触发 `failed(resourceCleanupTimeout)`，资源非零时拒绝同进程再次 start 并请求系统终止 tunnel；
- 终态和空资源引用在调用外部 completion 前已经发布，completion 同步重入安全；
- 旧 generation 的回调不能改变新 generation；
- 100 次后资源计数回到基线，无持续增长。

### IOS-03 IP packet 与 TCP flow

**环境**：物理 iPad；IPv4 与 IPv6 网络；可控 destination server。

**操作**

- IPv4、IPv6、domain 各执行 connect、正常 close 和 half-close；
- 注入重传、乱序、丢包和 destination reset；
- 下载至少 10 GiB 单文件并核对 hash；
- 建立至少 500 个并发 TCP flow；
- 让一个 flow 长时间阻塞，同时在其他 flow 传输；
- 输入 malformed IP/TCP packet 和超出 MTU 的 packet。

**通过条件**

- TCP byte stream 与 half-close 正确；
- 单个阻塞或失败 flow 不阻塞无关 flow；
- malformed packet 被拒绝且 extension 不 crash；
- 不发生无界 packet/flow buffer 增长；
- 500 flow 测试期间 memory、CPU、queue high-water 有记录；
- 超限的新 flow 按资源不足失败，不改变已有 flow 的 action。

### IOS-04 DNS UDP/TCP 语义

**环境**：物理 iPad + 可控 DIRECT/PROXY DNS resolver。

**操作**

分别通过 UDP 和 TCP 测试 A、AAAA、CNAME、HTTPS/SVCB、其他 qtype、NXDOMAIN、NODATA、SERVFAIL、REFUSED、EDNS(0)、`TC=1`、超时、响应 question 不匹配、压缩指针指向 header/非名称字段/当前或未来位置/循环/越界、截断报文、多问题查询和 256 个并发查询。

parser、compression 和 action 决策必须先通过 LNX-08；本项验证 Apple 上游 I/O 和真实 route。对同一 QNAME 分别配置 `DIRECT`、`PROXY`、`REJECT`。

**通过条件**

- `DIRECT` 查询只到 direct resolver；
- `PROXY` 查询只经 relay；所有允许转发的 qtype 都携带 action，不因“不合成 FakeIP”而默认直连；
- `REJECT` 返回 REFUSED 且不创建上游 socket；
- `TC=1` 沿同一 action 用 TCP retry，不发生 DIRECT/PROXY 切换；
- transport/timeout/校验失败返回 SERVFAIL；
- malformed query，包括指向非名称区域的 compression pointer，返回 FORMERR 或确定失败，不 forward 且不污染 cache；
- 只有经校验的 positive A/AAAA response 分配 FakeIP；NXDOMAIN/NODATA 不分配；
- DNS QNAME 不出现在日志和诊断中。

### IOS-05 FakeIP 生命周期与域名恢复

**环境**：物理 iPad + 可控 DNS TTL + packet/flow diagnostics。

**操作**

1. 对同一 domain 重复查询 A 和 AAAA；
2. 对不同 domain 批量分配直至每族 4,096、合计 8,192 映射上限；
3. 测试 TTL=0、短 TTL、超过 3600 秒 TTL，以及正向复用/反查不会续期；
4. TTL 到期时通过原子反查取得 active lease，再结束 flow 并等待 correlation grace 与 60 秒 quarantine；
5. 交错执行 TTL 到期、并发新分配、旧地址反查取 lease 和旧 flow release；
6. 重启 extension；
7. 构造 FakeIP pool 与本地路由冲突；
8. 连接未知或已回收的 FakeIP。

**通过条件**

- 同一 domain/family 在有效期内复用 FakeIP；A/AAAA 相互独立；
- DNS answer TTL 不超过上游 RRset 最小 TTL 和 3600 秒；TTL=0 不被提高；普通访问不重置权威 expiry；
- flow lease 的取得与反查原子完成；有 lease 时不回收，释放后仍满足 grace/quarantine 才复用；
- 并发交错中旧 FakeIP 不会错误关联到新 domain；
- 容量耗尽返回 SERVFAIL，不 LRU 驱逐未过期或有 lease 的映射；
- pool 或 tunnel route 与本地网络冲突导致 tunnel 启动失败；
- 未知 FakeIP flow fail closed，不直连、不交给 relay；
- flow 路由输入包含恢复出的规范化 domain，但诊断不输出其值。

### IOS-06 规则导入原子性

**环境**：Xcode unit/integration test + 物理 iPad 并发 flow。

**操作**

- 导入有效规则并在持续创建 flow 时切换；
- 在 JSON 解析、schema、语义编译、32 MiB 输入、20,000 条 iOS runtime 上限、32 MiB 编译 snapshot、candidate 写盘/同步、manifest rename/目录同步、digest 校验和 publish 各阶段注入失败；
- import 期间 kill containing app，覆盖 candidate 文件写完前后及 manifest commit 前后；
- 分别损坏 manifest 引用的 current 和 current/previous 两份；
- 更新规则后保持旧 flow 继续传输。

**通过条件**

- reader 只看到完整旧 snapshot 或完整新 snapshot；
- prepare/commit 任一步失败，旧 snapshot 保持活动；
- app 被终止后，下次启动只按完整 manifest 得到 current 或 previous；未被引用的 candidate 不得自动激活；
- current 损坏时可校验并加载 previous；两者都无效时 tunnel 启动失败；
- 已建立 flow 保持创建时的 snapshot ID 和 action；新 flow 使用新 snapshot；
- 超过资源限制时导入失败，无空规则或宽松 fallback；
- 完整性摘要只用于损坏检测，结果不得被描述为发布者签名验证。

### IOS-07 DIRECT / PROXY / REJECT 隔离

**环境**：物理 iPad + 可分别观测 direct destination、relay 和 DNS resolver 的测试网络。

**操作**

对 TCP、UDP 和 DNS 分别构造三个 action。随后逐项注入 direct DNS failure、direct connect timeout、relay 不可达、TLS trust failure、hostname mismatch、错误 ALPN、错误 token、relay `FORBIDDEN`、`DIAL_FAILED`、畸形 response 和 UDP association 关闭。

**通过条件**

- `DIRECT` 只产生 direct traffic，失败时不连接 relay；
- `PROXY` 只连接 relay，失败时不直连 destination/resolver；
- `REJECT` 不创建任何 outbound socket；
- REJECT TCP 返回可观察 RST/拒绝；UDP 注入 ICMP/ICMPv6 administratively prohibited，若目标 stack 不支持则按文档计数丢弃；DNS 返回 REFUSED；
- 所有 connector failure 只终止对应 flow/association，不改变 action；
- packet capture、server access log 和聚合 client diagnostic 三份证据一致。

### IOS-08 TLS transport 与 Go relay 互操作

**环境**：物理 iPad + 真实 Go relay + 可切换的测试证书/ALPN/token。

**操作**

- 正常 TLS 1.3、正确 hostname、系统信任和 ALPN；
- 错误 CA、过期证书、hostname mismatch、错误 ALPN、TLS 1.2-only server；
- 正确/错误/已撤销 token；
- handshake、auth response timeout 和 stop cancellation；
- TCP/UDP 各重复 100 次。

**通过条件**

- 只有 TLS 1.3、正常 trust/hostname、`ipad-proxy/1` 和 `StatusOK` 进入 ready；
- token 只在 TLS 建立后发送；
- 所有错误都 fail closed 且不改走 DIRECT；
- connect、TLS、auth 各自 10 秒 deadline 生效，且 negotiated ALPN 有独立断言；
- 取消会关闭 NWConnection，不遗留 continuation/task；
- token、auth request 和服务端详细 message 不出现在日志/UI/诊断。

### IOS-09 UDP-over-TLS

**环境**：物理 iPad + Go relay + UDP echo/DNS/STUN/HTTP3/视频测试端点。

**操作**

- codec 单元测试覆盖空 payload、普通 datagram、65,507-byte protocol cap，以及 253-byte domain 的 65,342/65,343-byte 组合边界；
- 真机分别发送不超过路径 MTU、需要 IP fragmentation 和接近 protocol cap 的 datagram，记录实际 iPadOS/Network.framework 结果，不要求 65,507 bytes 必须穿越公网；
- 连续发送不同大小 datagram 并核对边界；
- 测试 DNS、STUN、HTTP/3 和视频通话；
- 注入未联系 endpoint 回包；
- 测试 idle 30 秒、60 秒、10 分钟配置边界；
- 触发每 association 32 datagrams/256 KiB、全局 4,096 datagrams/8 MiB、256 peers（含 60 秒 peer expiry）和 256 associations 上限；
- 在 TLS/TCP 丢包条件下观察其他 datagram 延迟。

**通过条件**

- datagram 不合并、不拆分且内容一致；
- codec 对组合 frame 上限的接受/拒绝与协议一致；真机超过可用路径上限时返回 EMSGSIZE/Packet Too Big 或确定失败，不要求 tunnel protocol 内分片；
- 未联系 endpoint 不能注入；
- idle、关闭、取消和协议错误会释放 socket、timer、peer set 和 queue；
- 达到 queue/peer/association 上限时执行设计中的拒绝/丢弃，不增长容器；
- 测试报告明确记录 TLS/TCP head-of-line blocking，不把它误报为无损独立 UDP transport；
- HTTP/3 成功只证明应用 UDP 可用。

### IOS-10 资源上限与过载

**环境**：Xcode memory/CPU instrumentation + 物理 iPad。

**操作**

逐项达到并超过设计中的 packet、flow、opening flow、per-flow buffer、global connector payload、UDP、DNS、FakeIP、TLS handshake 和规则快照上限。每项持续 10 分钟，同时保持一组正常 control flows。

**通过条件**

- 每个 queue 同时报告 admission 前的 item count、byte count、观测 high-water 和 rejected count；
- 被拒条目不计入 high-water，已接纳条目不得使计数超过 hard cap；
- backpressure、RST、SERVFAIL、unreachable、计数丢弃或 tunnel resource-limit failure 与设计一致；
- 不出现 OOM、watchdog termination、deadlock 或无界 Task/timer/map/array 增长；
- 与超载无关的已建立 flow 在设计允许范围内继续工作；
- 释放负载后资源回到基线。

### IOS-11 网络变化与单节点失败

**环境**：物理 iPad；Wi-Fi、蜂窝、captive portal；单台 relay。

**操作**

- Wi-Fi 切到蜂窝及反向切换；
- sleep/wake；
- captive portal 前后；
- relay 进程 restart；
- 防火墙阻断 relay 5 分钟后恢复；
- 改变设备 IP 和 resolver 可达性。

**通过条件**

- 已失效 connection/association 在 deadline 内结束并释放资源；
- v0.2 不迁移或恢复已有 flow，也不实现 v0.3 的 network-transition/reconnection state machine；
- `PROXY` 不可达时不回退 DIRECT；
- relay 恢复后新 flow 可建连；已有失败 flow 不伪装为透明恢复；
- `DIRECT` flow 的结果只由当前本机网络决定；
- UI 明确显示单节点不可达，不显示备用节点或自动切换；
- 网络变化期间 start/stop 状态机保持一致。

该项只验收单节点失败语义，不验收多节点可用性。

### IOS-12 日志与诊断脱敏

**环境**：物理 iPad + console、OSLog store、crash report、app diagnostic export。

**操作**

使用带唯一 canary 的 token、domain、DNS QNAME、目标 IP、规则 value 和 payload，执行正常、TLS 失败、认证失败、DNS 失败、resource-limit、crash/forced termination 流程，然后搜索所有日志与导出。

**通过条件**

- canary token、token hash、payload、QNAME、domain、完整目标 IP/端口组合、规则 value 和 FakeIP 映射零命中；
- 只存在 generation、短 snapshot ID、action、address family、target type、状态、耗时 bucket、queue high-water、固定错误枚举和聚合计数；
- 重复错误每 `(component,errorClass)` 每分钟最多 10 条，其余只累计；
- Release build 不启用可能输出敏感 Network.framework 描述的调试日志。

### IOS-13 8 小时 v0.2 稳定性测试

**环境**：目标物理 iPad + Release build + 单台生产等价配置 relay。

**操作**

持续 8 小时混合运行网页、长下载、500-flow 周期负载、UDP DNS、HTTP/3、STUN、视频通话、Wi-Fi/蜂窝切换、sleep/wake 和一次 relay restart。每分钟采集聚合指标。

**通过条件**

- 无 crash、watchdog termination、deadlock、认证绕过或 action fallback；
- active flow、task、timer、connection、queue 和 FakeIP 引用在负载结束后回到基线；
- memory 不呈持续单调增长；
- 所有 queue high-water 不超过设计上限；
- stop 在测试结束时 5 秒预算内完成；
- 报告包含 memory、CPU、battery、重连、失败类别和高水位的时间序列。

仓库当前没有足够数据预设绝对 memory/CPU/battery 数值。首轮必须记录基线并由维护者在发布前批准具体预算；仅写“看起来稳定”不能通过。72 小时 soak 按 roadmap 属于 v0.4；v0.2 未完成该门禁前不得使用“长期稳定”结论。

## 4. 发布判定

v0.2 只有在以下条件同时满足时才可发布：

- 第 2 节全部 `PASS`；
- IOS-01 至 IOS-13 全部在目标物理 iPad 上 `PASS`；
- 没有未关闭的 crash、deadlock、认证绕过、规则绕过、私网策略绕过、无界内存增长或敏感日志缺陷；
- 测试证据与 commit、设备、iPadOS、Xcode 和 relay 版本绑定；
- README/roadmap 的状态更新与证据一致。

以下内容不作为 v0.2 完成声明：目录或空类型已经存在、Linux `swift test` 通过、模板能编译、模拟器可启动、单次真机连通、HTTP/3 可用，或仅有设计文档。

## 5. v0.2 之外

以下能力不属于本验收计划，也不得在 v0.2 release note 中标为完成：

- QUIC stream/Datagram transport；
- 多 relay 自动故障切换；
- 规则包发布者签名、后台分发和自动更新；
- 服务端打包、备份与证书自动续期；
- 商店发布或通用安装包交付；
- 72 小时 soak 和长期稳定性结论（roadmap v0.4）。
