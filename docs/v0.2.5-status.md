# v0.2.5 本地 UDP 与 DNS Packet Tunnel 接线状态

v0.2.5 从已完成的 v0.2.4.1 TCP 生命周期实现恢复，补齐本地 SOCKS5 UDP、DNS 上游和 Fake DNS 接线。该状态只代表 Linux 可验证部分已通过；Apple 网络路径仍必须在 Xcode 和物理 iPad 上验证，当前不得作为已发布或已完成真机验收的 VPN。

## 已恢复实现

### SOCKS5 core

- control codec 解析并编码 UDP ASSOCIATE。UDP ASSOCIATE 允许 `0.0.0.0:0` 和 `::0`；CONNECT 继续拒绝 port 0；BIND 与未知 command 继续映射 REP `0x07`。
- `SOCKS5UDPDatagramCodec` 严格要求 `RSV=0`、`FRAG=0`，支持 IPv4、IPv6 和 domain target，拒绝 target port 0，并保留空 payload 与 datagram 边界。
- datagram 总长上限为 65,507 bytes，确保本地 IPv4 UDP payload 不超过协议上限。RSV、FRAG、截断和 oversize 都返回不包含 target/payload 的 typed error。

### 配置与 App

- `ProviderConfiguration` 增加 `directDNSHost` 与 `proxyDNSHost`，仅接受 IPv4/IPv6 literal。默认值分别为 `223.5.5.5` 和 `1.1.1.1`。
- 旧 v0.2.4.1 JSON 缺少这两个字段时使用上述固定默认值；已有字段为 null/非法值时拒绝；任何未知字段仍拒绝。
- App UI 可分别编辑两个 DNS literal。保存按钮复用严格的 `ProviderConfiguration` 校验，不把 DNS 配置或 token 写入 VPN profile。

### DNS transport 与 interception

- `TransportDNSUpstreamResolver` 构造时固定一个 `TunnelTransport` 和一个 port 53 地址。DIRECT 和 PROXY 各有独立实例，任何失败、超时或取消都不会改用另一 action。
- UDP 每次 query 单独 open/send/receive/close。TCP 每次 query 单独 open，发送两字节 DNS length frame，精确读取一个 frame，然后 close。成功、错误和取消路径都关闭底层 flow；响应上限 65,535 bytes。
- SOCKS CONNECT 到 Fake DNS `198.18.0.2:53` 或 `fd00:198:18:2::2:53` 时进入本地 DNS-over-TCP frame loop，不交给 Fake IP flow 恢复。
- SOCKS UDP 到同一 Fake DNS endpoint 时调用 `DNSProxyService.handleUDPQuery`。其他 target 通过 `ManagedFlowCoordinator` 固定一次路由 action。

### 本地 UDP relay 与生命周期

- UDP listener 只绑定 `127.0.0.1` ephemeral port。并发 UDP ASSOCIATE 共享同一个启动任务和 listener；reply 返回真实 endpoint，并保持 control TCP 到 EOF。
- 每个 control 持有独立 association token。同一时间只允许一个未指定 source 的 wildcard control；指定 source port 也不得重复。每个 control 在首个 UDP peer 到达时永久绑定一个 source endpoint，control EOF 会取消并等待其 peer/target task，防止 data plane 越过 control 生命周期。
- relay 最多保留 256 个 UDP peer 和 256 个 fixed-target managed UDP association；target open 前先占 reservation，所有成功、失败和取消路径都会转换或释放 reservation。peer 与 target 都按单调 uptime 计算 60 秒 idle timeout。
- 每个 peer 的读取串行，每个 target 同时最多一个上游 receive；Network.framework send 的 `contentProcessed` completion 提供发送背压，不创建无界 datagram queue。
- FRAG、RSV 或其他非法 SOCKS UDP packet 只丢弃当前 packet。target open/send/receive 错误只关闭该 target session，不影响其他 session，也不切换 action。
- bridge stop 取消并等待 TCP/UDP task，停止 UDP listener，关闭所有 target association，并调用 coordinator `closeAll()`。listener 在 ready 后失效会先清理 relay，再通过 Packet Tunnel fatal callback 关闭 tunnel。实现不记录 target、QNAME 或 payload。

### Packet Tunnel assembly

- `PacketTunnelEntry` 从两个 DNS literal 构造 `Address:53`、DIRECT/PROXY resolver、共享 `DNSProxyCore`/`DNSProxyService`、UDP relay 和 TCP bridge。任一配置或 runtime 构造错误在 network settings 安装前 fail closed。
- Fake DNS 已显式启用。HEV 配置改为 `udp: 'udp'`。XcodeGen App 与 Extension marketing version 均为 `0.2.5`。

## Xcode 与物理 iPad 门禁

当前 Linux 环境没有 Apple SDK，因此无法 typecheck 或 link Network.framework、NetworkExtension 和 Tun2SocksKit。必须在目标 Xcode/iPadOS 组合完成以下项目：

1. 解析并锁定 Tun2SocksKit 5.16.0，确认 HEV 接受 `udp: 'udp'`，使用 UDP ASSOCIATE reply 的 `127.0.0.1:port`，并保持 control TCP 生命周期。
2. 编译 App 与 PacketTunnelExtension，处理 Swift 6 complete concurrency 的任何 Apple SDK 诊断。
3. 在物理 iPad 验证 utun startup、IPv4/IPv6 TCP、UDP、DNS A/AAAA/HTTPS、DIRECT/PROXY action 隔离、Fake IP 恢复和 REJECT。
4. 验证 UDP 65,507 codec 边界与实际路径 MTU/IP fragmentation/`EMSGSIZE` 行为。codec 上限不表示所有尺寸都能通过真实网络路径。
5. 验证 UDP 256-session cap、60 秒 idle expiry、Network.framework send 背压、DNS 256 inflight cap、取消、错误、网络切换、休眠唤醒和内存压力。
6. 验证正常 stop、stop-during-start、重复 stop、运行期 HEV exit，以及所有 TCP/UDP/DNS flow 在预算内关闭。Tun2SocksKit 没有可靠的 positive-ready callback，短暂启动等待仍只能发现立即退出。

这些门禁通过前，README 和发布说明只能称 v0.2.5 为“本地恢复与接线”，不能称为已完成真机验收。
