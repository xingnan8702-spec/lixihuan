# Control-bound SOCKS UDP admission and bounded target sessions

The v0.2.5 worktree adds strict SOCKS5 UDP framing, literal DIRECT/PROXY DNS configuration, per-query DNS transports, Fake DNS interception, and HEV UDP wiring on top of the v0.2.4.1 TCP path. This third pass verifies that the two remaining product blockers are closed: UDP controls now reserve unique wildcard or specified source ownership before listener startup, and target sessions reserve capacity before awaiting transport creation. Apple target compilation and physical-device behavior remain a release gate because this environment has no Apple SDK.

Watch for: **confirmed** Apple-only relay, resolver, bridge, NetworkExtension, and Tun2SocksKit behavior still requires Xcode and physical-iPad validation before release; this does not block committing the local recovery.

**Verdict**: APPROVED

## High-level view

UDP control admission now prevents two wildcard requests or duplicate specified source ports from passing concurrently while listener startup is suspended. A control binds permanently to the first accepted source port, admits at most one live peer, and gives an exact specified-port control priority over the wildcard control.

Target-session admission now counts retained sessions together with pending opens. The relay inserts the reservation before `openUDP`, removes it on failure, and checks that the owning peer still exists before converting a successful open into a cached session, so concurrent opens cannot cross the 256-session bound.

## UDP control ownership across listener startup and peer arrival

The control reservation is established before `beginAssociation` awaits shared listener startup. Wildcard requests use one pending/active slot, while specified ports use a pending set plus the active control map, so actor reentrancy cannot admit duplicate ownership during startup. Both success and error paths clear the pending marker.

Once the UDP listener receives a peer, `matchingControl` first looks for an exact source-port declaration and only then considers the single wildcard control. It records the accepted source port in `boundSourcePort` and requires the control to have no live peer before admitting a connection. Removing a peer does not clear that binding, so a wildcard control cannot later migrate to another source endpoint.

## Reservation-based 256-session ceiling

A missing fixed-target session now requires `sessions.count + pendingTargetSessions.count` to remain below 256 and atomically inserts its `SessionKey` into the pending set before awaiting `coordinator.openUDP`. Concurrent peer tasks therefore consume capacity while transport creation is in flight instead of all observing the same free slot.

Open failure removes the reservation immediately. After a successful open, the relay removes the reservation and verifies that the peer still exists; if ownership ended while the await was suspended, it closes the new association rather than caching it. A valid open is converted to one response task and one retained session before the original datagram is sent.

## Apple runtime validation remains a release gate

**Confirmed:** SwiftPM tests exercise only the Foundation core, while `LocalSOCKS5UDPRelay`, `TransportDNSUpstreamResolver`, `LocalSOCKS5TCPBridge`, `PacketTunnelEntry`, and `HEVPacketStackAdapter` depend on Apple frameworks or Tun2SocksKit. Linux `swiftc -parse` validates syntax but cannot validate Apple SDK signatures, Swift 6 isolation at those framework boundaries, extension linkage, listener behavior, utun startup, or cancellation under real Network.framework callbacks.

Before release, build and test the App and Packet Tunnel targets in Xcode, then exercise the documented UDP/DNS, lifecycle, resource-bound, MTU, network-change, and stop/cancellation cases on a physical iPad. This is a release qualification task rather than a source-code blocker for committing the local v0.2.5 recovery.
