# v0.2.6 聚合诊断状态

v0.2.6 为现有 Packet Tunnel 数据路径增加隐私保护的运行期聚合诊断和 containing app IPC。此状态只表示 Swift core 测试和跨平台可执行的语法/配置检查通过；Apple NetworkExtension IPC、完整 Xcode typecheck/link 和物理 iPad 行为仍是发布门禁。

## Core snapshot 与计数

- `TunnelDiagnosticsSnapshot` 是 `Codable`、`Equatable`、`Sendable` 值，只包含 timestamp/uptime、TCP/UDP active 与 high-water、上下行 bytes/packets、DNS total/failures、rejected flows、resource rejections、transport failures 和固定 `TunnelTerminalErrorCategory`。
- schema 没有 domain、IP/address、port、token、path、payload 或底层 error description 字段。测试用敏感 canary 在编码结果中零命中。
- actor 的所有累计计数和 active 增加都使用饱和加法。active cleanup 使用饱和递减，不会下溢。
- reset 保留当前 TCP/UDP active，把 high-water 重置为当前 active，清空累计计数和 terminal error，并重新开始 uptime。
- 并发事件由 actor 串行化；测试覆盖 1,000 个并发 activate/traffic/DNS/cleanup 序列。

## 严格 IPC codec

- request 仅支持 schema version 1 的 `snapshot` 和 `reset` operation。
- success response 只包含 snapshot，failure response 只包含固定错误枚举；两者不能同时出现或同时缺失。
- request、response 和嵌套 snapshot 都拒绝未知字段。空消息、malformed JSON、不支持版本和超过 64 KiB 的输入明确失败。
- provider 对所有解码和运行期错误返回固定 response code，不序列化或显示底层错误描述。

## Managed flow 与 DNS

- `ManagedFlowCoordinator` 和 `DNSProxyService` 都通过末尾可选参数注入同一个 `TunnelDiagnostics`，原有调用无需修改。
- TCP/UDP 在 permit activation 成功后增加 active/high-water。managed wrapper 的单一 cleanup task 确保并发 close、EOF 和 I/O error 只递减一次。
- 成功的 managed send/receive 按 `Data.count` 记录 bytes，并按一次调用/数据报记录 packet。失败的调用不增加 byte/packet。
- policy/Fake IP fail-closed 计入 rejected flow；limiter admission/activation failure 计入 resource rejection；backend open 和 managed I/O failure 计入 transport failure。
- 每个 DNS UDP query 或 TCP frame 先计入 total。上游 resolver、timeout、response validation、malformed query 等失败对该 query 只增加一次 DNS failure。
- DNS inflight cap 计入 resource rejection。本地 REJECT 生成 REFUSED response，不计 DNS failure，也不计 transport failure。DIRECT/PROXY action、fallback 和错误传播语义没有改变。

## Apple extension 与 app

- `PacketTunnelDependencies` 携带 core diagnostics 和 `TunnelDiagnosticsSource`；provider 强持有两者。
- `HEVPacketStackAdapter` 提供 source snapshot，以 core 累计值为权威来源，并读取 coordinator/limiter snapshot 校验 live active gauge。这样不会把同一 managed event 重复计数，reset 也不会重新引入 limiter lifetime totals。
- 已解析的 Tun2SocksKit 5.16.0 依赖不提供稳定 `Socks5Tunnel.stats` API。v0.2.6 因此不猜测 HEV packet/byte 数据，也不把不可验证值混入 core aggregate。
- provider startup、network-settings failure、bridge startup failure、UDP relay fatal、HEV immediate/runtime exit 和 HEV stop timeout 使用固定 terminal category。normal start/stop 调用 lifecycle event API，但 snapshot 不增加非需求字段。
- `handleAppMessage` 严格解码 bounded request，并用 one-shot completion 返回 snapshot/reset 或固定错误 response。
- `TunnelManager` 仅在 `connected`/`reasserting` 时使用 `NETunnelProviderSession.sendProviderMessage`。callback continuation 通过锁保护，只完成一次；nil、malformed、oversized 和 provider failure 都映射为不含描述的 typed error。
- `AppViewModel` 在 app active 且 tunnel connected/reasserting 时每两秒刷新。后台或断开时取消 polling 和当前 refresh，并清除断开 generation 的 snapshot。UI 支持手动 refresh/reset。
- SwiftUI Diagnostics section 仅显示格式化上传/下载 bytes、active TCP/UDP、DNS failures/total、flow/resource rejection 和固定 last error category。

## Xcode 与物理 iPad 门禁

Linux 没有 Apple SDK，`swiftc -parse` 不会验证 NetworkExtension 方法签名、Swift 6 complete concurrency 跨 Apple callback 的类型检查、Tun2SocksKit 链接或 extension entitlement。发布前必须在 macOS/Xcode 和物理 iPad 完成：

1. 生成并编译 `IPadProxy` 与 `PacketTunnelExtension`，处理完整 strict-concurrency 诊断。
2. 验证 connected/reasserting snapshot/reset、断开拒绝、并发 request、extension restart、版本不匹配、未知字段、64 KiB 边界和 provider completion exactly once。
3. 验证 app 前后台、sleep/wake、网络切换和 disconnect 会停止两秒 polling，不显示旧 generation snapshot。
4. 验证 TCP/UDP/DNS 计数与真实流量一致，half-close/EOF/并发 cleanup 不重复减少 active，reset 后 live active 保留。
5. 触发 network settings、bridge、UDP listener、HEV immediate/runtime/quit-timeout 路径，确认只出现固定类别且 response 中没有 endpoint、QNAME、token、App Group path、payload 或 framework description。
6. 继续执行 v0.2.5 的 IPv4/IPv6、Fake DNS、MTU、内存上限、资源 cap、stop cancellation 和 DIRECT/PROXY action 隔离门禁。

这些 Apple 门禁完成前，v0.2.6 只能称为本地实现和验证，不能称为已完成真机验收。
