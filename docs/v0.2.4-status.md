# v0.2.4.1 本地 TCP-only Packet Tunnel 接线状态

v0.2.4.1 修复 v0.2.4 的 TCP half-close、SOCKS5 reply 和 HEV 生命周期问题，但仍不是完整或可用的 VPN。UDP ASSOCIATE 会明确返回 command not supported；UDP packet path 和普通 DNS packet service 均未接入，因此 UDP 和 DNS 仍不可用。

## v0.2.4.1 修复

- `ManagedTCPByteStream` 将 remote receive EOF 只记录为 read finished，不再立即 full cleanup。此后仍允许 client→remote send；`finishSending()` 开始后拒绝新 send，成功后记录 write finished。读写两边都结束才关闭底层 stream、释放 Fake IP lease/flow permit 并注销 registry。显式 close 或任意底层 I/O error 仍立即 full cleanup，并发 EOF/finish/close 共享同一 cleanup gate。
- SOCKS5 request 与 reply 的地址约束分离：request 仍拒绝 port 0，reply 允许 `BND.ADDR=0.0.0.0, BND.PORT=0`。bridge 的成功和失败 reply 都使用该未指定 endpoint，不再把 loopback listener 冒充 outbound endpoint。
- BIND、UDP ASSOCIATE 和未知 command 都映射为 REP `0x07`；未知 ATYP 仍映射 REP `0x08`。core 测试检查 exact reply bytes，并继续检查 zero-port request 拒绝。
- `HEVPacketStackAdapter` 增加稳定的 `unexpectedRuntimeExit(code)` 和 `exitWaitTimedOut` error、MainActor one-shot fatal callback，以及可查询的 terminal error。运行期非预期退出先停止 bridge、关闭 coordinator flows，再由 `PacketTunnelEntry` 调用 `cancelTunnelWithError` 通知 NetworkExtension。正常 quit completion 不触发 fatal。
- HEV stop 最多等待 exit gate 5 秒。gate waiter 到时会被移除和恢复，不保留无限 continuation；即使超时也继续停止 bridge、关闭 coordinator 并返回。并发/重复 stop 共用 stop task。bridge start 恢复后会重新检查 generation，stop-during-start 不会在停止后启动 HEV。
- `defaultNetworkSettings(remoteAddress:installFakeDNS:)` 只有在显式启用时才安装 Fake DNS。v0.2.4.1 TCP-only entry 传 `false`，因此不设置 `198.18.0.2`、`fd00:198:18:2::2` 或 wildcard `matchDomains`，不会把系统 DNS 指向不存在的 listener。
- XcodeGen App 与 Extension 的 marketing version 更新为 `0.2.4.1`。

## 必须在 Xcode 与真机完成的门禁

Tun2SocksKit 5.16.0 的公开 API 只在 `Socks5Tunnel.run` 退出时给 completion，没有“utun 已取得且 worker 已 ready”的成功回调。当前 adapter 的短暂等待只能发现立即退出，不能证明 ready。必须在目标 Xcode/iOS 组合和物理 iPad 上验证 package resolution、Apple API typecheck/link、utun fd 获取、启动即失败、运行期 completion→`cancelTunnelWithError`、正常 quit、5 秒超时、迟到/重复 completion、stop-during-start、重复 stop、TCP IPv4/IPv6、双向 half-close、取消、网络切换、休眠唤醒和内存上限。

Fake IP core 和 DNS service 代码的存在不代表 Packet Tunnel 已接入 DNS。TCP-only entry 现在刻意不发布 Fake DNS settings；普通 DNS、UDP、DNS Fake-IP 合成 listener 与 HEV packet path 仍未接通。在这些项目完成前，文档、UI 和发布说明不得把 v0.2.4.1 称为完整或可用的 VPN。
